# Firmeza API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the Firmeza hardware store API for products, customers, sales, vehicles, and rentals, including authentication, receipts, data exchange, and deployment.

**Architecture:** A modular monolith separates Domain, Application, Infrastructure, and API. Infrastructure implements Application interfaces; controllers delegate business operations to Application services. Identity and EF Core do not enter Domain.

**Tech Stack:** .NET 10, ASP.NET Core, PostgreSQL, EF Core/Npgsql, Identity, JWT, AutoMapper, Swagger, xUnit, Docker, SMTP, PDF and Excel libraries verified before installation.

**Spec:** [Approved design](../specs/2026-10-05-firmeza-api-design.md).

## Global Constraints

- Retain the existing .NET 10 target.
- Use English identifiers, source comments, API contracts, and database names.
- Use the requested folders: `Abstractions`, `Entities`, `ValueObjects`, `Enums`, `Errors`, `Exceptions`, and `Constants`.
- Create all schema through EF Core migrations.
- Clients submit product identifiers and quantities; the server determines all prices and totals.
- Customer identifiers are derived from authenticated identity for customer requests.
- Connection strings, signing keys, SMTP credentials, and bootstrap passwords come from environment configuration or user secrets.
- Razor and frontend containers are outside this repository's current delivery scope.

## Review Focus

1. Integer/decimal overflow and oversized strings must produce validation errors before any writes (Tasks 1–2).
2. Reusing an idempotency key with different items must return conflict rather than an unrelated sale (Task 4).
3. UTC boundaries and adjacent rental dates must preserve the end-exclusive rule (Tasks 1 and 4).
4. A deleted/deactivated account or customer must not bypass ownership through a still-valid JWT (Task 5).
5. Malformed/oversized Excel files and formula-like text in exports must not corrupt data or execute spreadsheet formulas (Task 7).

## File layout

- `Firmeza.Domain/`: one entity/value object/error abstraction per file under the approved folders.
- `Firmeza.Application/Abstractions/`: interfaces for transactions, feature repositories, current customer, identity, receipts, email, exchange, and delivery queue.
- `Firmeza.Application/{Products,Customers,Sales,Vehicles,Rentals,Authentication,Reporting}/`: request/response DTOs, services, validators, and mapping profiles grouped by feature.
- `Firmeza.Infrastructure/{Persistence,Identity,Documents,Email,DataExchange}/`: implementations, EF configurations, migrations, and background delivery.
- `FirmezaApi/{Controllers,Authorization,Configuration}/`: retain the existing API project path and assembly to avoid unnecessary file moves; namespace `Firmeza.Api`.
- `Firmeza.Tests/{Domain,Application,Integration}/`: test classes grouped by behavior.
- `docs/`, root Docker files, `.env.example`, `README.md`: setup and consumption instructions.
